# 执行摘要（Phase 1：研究设计版）

> 本文件用于说明研究方向和待验证假设，不代表最终研究结论。

## 研究主题

AI Coding Agent 正从代码补全工具扩展为能够理解代码库、调用工具、执行多步骤任务并提交可审查变更的软件开发参与者。本研究将同时分析产品能力、用户需求、公司竞争资源和人才结构，重点关注“产品如何创造可持续价值”以及“企业需要怎样的人才和组织能力”。

## 研究对象

初始样本覆盖以下产品形态：

- AI-native editor
- CLI / terminal coding agent
- GitHub或代码托管平台中的云端Agent
- 自主软件工程Agent
- 浏览器端应用构建Agent
- 开源及可自托管工具
- 企业开发者平台

产品样本及状态在 `data/product-mapping.csv` 中维护。当前归类均为研究起点，后续根据官方资料和实际测试调整。

## 研究方法

研究将采用四类方法：

1. **官方资料核验：** 产品文档、更新日志、价格、安全说明、公司公告和招聘页面；
2. **产品体验：** 使用统一任务记录任务理解、计划、执行、工具调用、测试、人工干预和最终结果；
3. **岗位内容分析：** 对公开职位描述进行职责、能力和背景标签编码；
4. **三角验证：** 使用官方资料、实际观察、可复现评测和第三方证据交叉核对。

## 待验证假设

### H1：竞争重点将从“能否生成代码”转向“能否完成可验证的工程任务”

需要验证的指标包括代码库理解、多文件修改、测试闭环、变更控制、错误恢复和可审查证据。

### H2：产品入口决定使用场景，模型能力并非唯一壁垒

IDE、CLI、GitHub、浏览器和异步云端Agent拥有不同的上下文、权限和协作方式。入口、工具链和工作流集成可能决定产品在企业中的实际价值。

### H3：企业采用的核心障碍是可控性和治理，而不仅是生成质量

需要研究权限、数据政策、审计、成本管理、测试标准和责任边界如何影响组织级采用。

### H4：不同用户需要不同程度的Agent自主性

非专业用户可能更需要从自然语言到可运行应用的完整闭环；专业工程师可能更重视代码库理解、精确变更、可审查性和对现有工程体系的适配。

### H5：AI应用人才需要技术、产品、研究和业务能力的组合

单纯掌握某个AI工具可能不足以形成长期竞争力。能够研究产品能力、理解用户工作流、建立评测、开发内部工具并解释商业价值的人才可能更稀缺。

### H6：人才战略工作将更加依赖技术理解和结构化研究

AI人才Mapping不仅需要识别公司和岗位名称，还需要理解模型、Agent、开发工具和企业落地环节，从而构建可用的人才画像和目标公司分层。

## 预期成果

最终版本计划输出：

- 产品生态地图与能力矩阵；
- Tier A产品的场景化体验报告；
- 公司类型、产品组合和竞争资源Mapping；
- 公开岗位样本与能力标签统计；
- AI Coding Agent人才角色地图；
- 对产品团队、企业采用和人才战略的建议。

## 当前限制

- 产品和价格变化较快，必须维护采集日期；
- 当前产品样本尚未全部完成官方核验；
- 产品体验可能受套餐、模型、地区和项目类型影响；
- 初始岗位样本数量不足，不能推断整体招聘趋势；
- 本阶段只建立框架，不发布综合排名或确定性行业结论。
