# 执行摘要：从代码辅助到 Agent 系统

> 版本：v0.1  
> 观察截止：2026-07-30  
> 完整报告：[`report/full-report-draft-v0.2.md`](full-report-draft-v0.2.md)  
> 主张—证据索引：[`data/claim-evidence-index-v0.1.csv`](../data/claim-evidence-index-v0.1.csv)

## 研究问题

本研究考察：

> **AI Coding Agent 的产品能力演进，正在如何改变企业的组织能力瓶颈、岗位组合和人才需求？**

研究不进行模型跑分或产品排名，而是连接三个层次：

> **产品能力变化 → 组织能力瓶颈 → 岗位与人才识别**

## 样本与方法

产品样本包括 OpenAI Codex、Anthropic Claude Code、Cursor、Qoder、GitHub Copilot 和 Cognition Devin。岗位样本共 20 份，其中 17 份为完整官方 JD，3 份为正文不完整但可确认的官方材料。

岗位样本是为了覆盖不同能力瓶颈而进行的定向选择，不能用于推断行业岗位比例、需求规模或增长率。研究先进行开放编码，再使用六维能力框架对 17 份 A 级 JD 进行第二遍编码，并建立 44 项主张—证据索引。

## 四项主要发现

### 1. 产品正在从代码辅助扩展到 Agent 交付系统

六个核心产品虽然起点和能力边界不同，但均在不同程度上扩展：

- 完整任务和异步委托；
- 代码库与项目上下文；
- 工具调用与执行环境；
- 测试、审查和交互验证；
- 并行任务与状态管理；
- 权限、审批、审计和停止机制。

因此，分析单位不应只是一段代码或一次生成，而应包括：

> **目标＋上下文＋工具＋环境＋权限＋验证＋治理**

这是一项产品方向判断，不代表产品在真实任务中的可靠性相同，也不构成产品优劣排名。

### 2. 执行能力增强后，瓶颈会迁移，但不会统一消失

对于目标清晰、上下文充足且结果可验证的任务，限制因素更可能迁移到：

- 任务定义与范围控制；
- 组织知识与上下文维护；
- 环境配置与工具集成；
- 权限和安全边界；
- 并行编排、状态观察和异常处理；
- 独立验证与完成证据；
- 审查与集成容量；
- 长期自动化的责任锚点；
- 成本与价值治理。

对于创新性、高风险和低可验证任务，专业技术判断仍可能是主要瓶颈。Agent 化不等于编码问题已经被普遍解决。

### 3. 企业主要通过既有职能的责任扩展作出响应

对 20 份岗位的开放编码形成六类任务群：

1. Agent 运行系统；
2. 测量、验证与交付质量；
3. 安全、权限和控制；
4. 企业部署与采用；
5. 用户与产品学习；
6. 组织运营与人才决策。

当前样本显示，相关责任主要分布在工程、产品、安全、客户、运营和 People 职能中。证据更支持“既有职能增加新的工作对象和责任”，而不是一个已经成熟、独立的 Agent 职业体系。

核心平台、评测、CI/CD 和控制平面岗位仍保持较高专业门槛；跨边界转换则更集中于产品、部署、采用、研究转化和组织决策岗位。

### 4. 人才 Mapping 应从能力瓶颈进一步深入到问题解决证据

岗位名称、专业、年限和公司背景可以提高检索效率，但不能单独证明候选人解决过什么问题、承担过多深的责任或产生过什么结果。

本研究提出以下方法链：

> **能力瓶颈 → 岗位能力原型 → 必需能力组合 → 专业与责任情境 → 直接人才来源 → 相邻人才来源 → 候选人证据 → 风险与待验证项**

判断人才迁移时，除了抽象能力维度，还需要比较：

- 具体专业领域 T-Domain；
- Agent 系统建设 A-S 与 Agent 工作流 A-W；
- 评测证据 G-E 与风险控制 G-R；
- 端到端责任对象 D-Scope；
- 行为、工作产物、结果和可归因证据。

该方法用于补充传统岗位名称搜索，尚未通过真实招聘项目的对照实验，不应被表述为已经验证的行业最佳实践。

## 探索性岗位能力原型

研究提出六类探索性原型：

| 原型 | 核心问题 |
|---|---|
| Agent 系统建设者 | Agent 循环、工具、会话、环境和控制平面 |
| 评测与可靠性交付者 | 数据集、评测、测试、回归、CI/CD 和发布证据 |
| Agent 产品与控制设计者 | Agent 行为、权限、人机工作流和产品定义 |
| 技术型部署与采用连接者 | 从试点到生产、集成、工作流和采用 |
| 证据—决策转换者 | 将产品、用户、质量或人才证据转化为决策 |
| 组织规划与运营转化者 | 将战略转化为人员、资源、流程和运营计划 |

这些原型来自小型定向样本，不是稳定、穷尽或经过跨行业验证的分类，也不能用于计算统一人才总分。

## 研究边界

- 20 份 JD 不具统计代表性；
- 中国官方岗位样本明显不足；
- 公开 JD 反映岗位意图，不等于真实组织结构或招聘结果；
- 编码主要由同一研究过程完成，尚未进行独立编码者一致性检验；
- 产品官方资料不能独立证明真实可靠性、企业采用深度、事故率或 ROI；
- “同名岗位跨公司职责差异”尚缺配对样本；
- 个人案例只用于解释机制；
- 目标岗位官方链接未恢复，只作为方法应用示例。

## 核心结论

> **AI Coding Agent 相关岗位并不对应一种统一的“AI 能力”。随着产品从代码辅助扩展到 Agent 交付系统，组织需要围绕运行、评测、治理、部署、采用和决策配置不同能力组合；人才识别也应从岗位标签进一步深入到能力瓶颈和问题解决证据。**
