# AI组织能力情报岗位与目标岗位应用 v0.1

> 状态：作者已确认的交付六  
> 更新时间：2026-07-30  
> 证据边界：本轮使用作者提供的“AI应用人才战略实习生—AI创新业务”岗位文本作为方法应用输入。尚未恢复可核验的官方岗位链接，因此不能确认岗位当前开放状态、地点和最终版本，也不能据此推断字节跳动内部组织架构。  
> “AI组织能力情报岗位”是本研究使用的解释性名称，不是官方岗位名称。

## 1. 岗位面对的核心组织问题

岗位文本包含四组职责：

1. 研究AI产品、用户需求和产品解决方案；
2. 跟踪AI进展、产品动态、行业趋势、市场和公司；
3. 参与AI及智能硬件领域的人才策略与Mapping；
4. 开发内部AI工具，提高工作流效率。

这些职责共同面对的能力瓶颈是：

> **AI产品能力快速变化，使业务下一阶段需要的组织能力、岗位组合和人才来源也随之变化；传统依靠岗位名称、既有人才库和人工搜索的方法，难以及时形成可验证、可持续更新的判断。**

岗位实际承担的转换链为：

> **外部AI产品变化 → 产品能力和用户价值解释 → 业务能力瓶颈判断 → 组织能力和岗位组合推断 → 人才来源与候选人证据 → 内部工具化和持续更新 → 支持People与业务决策。**

核心产出不是单独一份行业报告、一张人才名单或一个自动化脚本，而是：

> **从AI产品变化到组织与人才决策的可追溯证据链。**

## 2. 角色定义

本研究将这类岗位描述为：

> **站在People职能内的AI产品研究员、组织能力分析员和内部AI工具实践者。**

完整定义：

> **持续识别AI产品和产业变化，将其转化为业务能力瓶颈、组织能力需求和人才供给判断，并通过可复核的研究方法和内部工具支持组织决策的复合型岗位。**

岗位同时面向三个对象：

| 对象 | 需要回答的问题 |
|---|---|
| 产品与产业 | AI产品已经能做什么、不能做什么，用户和工作流如何变化 |
| 组织与业务 | 这些变化会使哪些能力成为瓶颈，需要什么岗位或职能承担 |
| 人才与People | 哪些人解决过相似问题，如何验证其能力，而不是只找同名岗位 |

内部AI工具负责将上述分析变成可重复、可更新的流程。

## 3. 四组职责构成的工作闭环

### 3.1 AI产品研究：识别变化

研究对象不应只包括模型参数或产品功能列表，还应分析：

- 产品的委托单位发生了什么变化；
- Agent获得了哪些工具、环境和权限；
- 用户需要承担哪些目标定义、监督和验证工作；
- 新增了哪些失败模式和治理要求；
- 产品能力解决了什么业务问题。

这一部分回答：**外部能力发生了什么变化？**

### 3.2 公司和行业研究：识别组织信号

公司研究继续回答：

- 哪类公司正在建设Agent系统、评测、部署、治理或采用能力；
- 相同问题由哪些不同岗位名称承担；
- 哪些职责是新出现的，哪些是传统职能的新工作对象；
- 公司公开岗位能够支持什么判断，不能支持什么判断。

这一部分回答：**企业正在用什么组织能力应对变化？**

### 3.3 人才策略与Mapping：识别能力来源

人才研究应继续追踪：

- 目标业务真正受到什么能力瓶颈限制；
- 需要哪种能力原型；
- 哪些人才属于直接来源；
- 哪些相邻经历具有相同问题解决机制；
- 候选人是否留下行为、产物和结果证据；
- 迁移差距如何验证。

这一部分回答：**什么人曾经解决过结构相似的问题？**

### 3.4 内部AI工具：使情报工作可持续

手工研究难以长期维护产品变化、招聘页面失效、岗位职责调整和证据版本。内部工具应使研究流程具备：

- 可重复；
- 可追溯；
- 可更新；
- 可协作；
- 可审计；
- 可人工复核。

这一部分回答：**如何让组织能力情报从一次性报告变成持续运行的工作系统？**

## 4. 六维能力组合应用

以下编码基于作者提供的岗位文本，属于研究者推断D，而不是官方岗位评分。

| 维度 | 暂定要求 | 判断依据 |
|---|---|---|
| V 价值选择 | `V1/2I` | 需要判断产品、趋势、公司和人才问题的研究优先级，但实习岗位未必拥有最终战略决策权 |
| P 问题结构化 | `P2I` | 将宽泛AI动态转化为研究问题、公司框架、人才画像和工具需求 |
| T 技术判断 | `T1I[AI应用/开发者工具/数据自动化]` | 需要理解产品能力边界并具备基础开发或自动化能力，但无证据要求建设核心模型或Agent平台 |
| A-S Agent System | `A-S0/NA` | 文本未证明需要建设Agent运行时、模型路由、Memory或控制平面 |
| A-W Agent Workflow | `A-W1/2I` | 需要使用AI工具重构研究、信息处理和Mapping工作流 |
| G-E 证据与评测 | `G-E2I` | 公司、产品和人才判断依赖来源核验、编码、比较和结论边界 |
| G-R 风险与控制 | `G-R1I` | 内部工具和人才数据涉及权限、来源记录、隐私及人工复核，但文本未显示其为首要职责 |
| O 组织连接 | `O2I` | 需要把技术、产品、市场和人才语言转换为People及业务可执行判断 |
| M 研究与测量 | `M2I` | 深度研究、趋势跟踪、报告和Mapping要求系统研究方法 |
| D 交付责任 | `D1I[Research/Organization]` | 需要交付研究、Mapping和工具产物，但最终组织决策责任可能由正式员工承担 |
| C 客户商业情境 | `C0/1I` | 主要服务内部业务与People团队，不属于外部客户部署岗位 |

暂定能力画像：

> `V1/2 + P2 + T1[AI应用/开发者工具/自动化] + A-W1/2 + G-E2 + G-R1 + O2；M2，D1[Research/Organization]，C0/1`

关键组合是：

> **研究方法＋AI产品理解＋问题结构化＋组织转换＋工具化能力。**

## 5. 能力原型组合

### 主原型：证据—决策转换者

核心是定义研究问题、评价来源质量、处理矛盾证据、识别结论边界，并将产品、公司、岗位和人才资料转化为组织决策输入。

### 第二原型：组织规划与运营转化者

研究结果需要进一步转化为组织能力需求、岗位能力原型、人才来源假设、市场供给风险和后续验证计划。

### 辅助原型：Agent工作流设计者

内部AI工具职责要求发现重复性研究摩擦、结构化人工步骤、设计AI与人工分工、保留来源和审核节点。但现有证据不足以把岗位归为Agent系统建设者。

## 6. 不可替代的核心能力

### 6.1 研究与证据能力

- 从模糊问题形成研究框架；
- 区分官方、第三方和推断证据；
- 处理动态信息和失效页面；
- 发现反例；
- 明确写出“不足以判断”。

### 6.2 AI产品与技术可信度

- 理解模型、Agent、工具调用、上下文、执行环境和验证的区别；
- 判断产品能力边界；
- 阅读开发者文档；
- 进行基础产品实践或原型验证；
- 与技术团队进行可信对话。

### 6.3 产品—组织—人才转换能力

解释产品变化为何成为业务问题，业务问题需要什么组织能力，组织能力应由什么岗位组合承担，以及哪些经历能够证明人才具备相应能力。

### 6.4 工具化和流程意识

设计研究工作流、结构化数据、建立来源记录、自动化重复步骤、设置人工复核，并对工具输出负责。

## 7. 标签的使用边界

以下标签不能直接作为核心能力证据：

- 商科或计算机专业名称；
- 使用过某款Coding Agent；
- 在知名AI公司实习；
- 会写行业报告；
- 做过传统招聘Mapping；
- 会Python或低代码工具；
- 英语成绩或证书；
- 工作或实习月数。

这些标签只能产生初始假设，必须继续检查候选人的行为、产物和结果。

## 8. 人才来源

### 8.1 直接来源

- AI或技术业务中的人才情报、人才策略，并参与产品和公司研究；
- People Research或Workforce Planning中的AI组织能力和人才供给研究；
- 将AI战略或产品研究直接转化为人才或组织决策的岗位；
- 在People、战略或运营职能中建设内部AI研究与Mapping工具。

直接来源仍需证明并非只做名单搜集或报告整理。

### 8.2 相邻来源

| 相邻来源 | 已有优势 | 主要缺口 |
|---|---|---|
| AI产品或行业研究 | 产品、市场、公司分析 | 缺少组织和人才决策经验 |
| 技术型人才研究或招聘研究 | 人才市场、岗位和公司Mapping | AI产品理解和研究方法可能不足 |
| People Analytics / Workforce Planning | 组织数据、规划和决策支持 | 外部产品及产业研究能力不足 |
| 战略运营或竞争情报 | 战略、公司研究和跨团队推动 | 人才供给及候选人证据判断不足 |
| 用户研究或产品分析 | 研究方法和证据生成 | 组织能力和人才Mapping经验不足 |
| 内部AI工具或AI Enablement | 工作流和工具实践 | 市场研究、People和人才情境不足 |

### 8.3 高风险来源

- 只会按照岗位名称寻找候选人的传统Sourcing经历；
- 只制作宏观行业报告，没有原始证据和决策影响；
- 只会使用AI工具，没有研究方法或结果责任；
- 纯工程背景，不能转换为业务、组织和人才语言；
- 纯HR通才，只掌握表层AI概念；
- 只展示自动化脚本，不能说明工具支持了什么判断；
- 依赖公司品牌，不能拆分个人贡献。

## 9. 候选人证据

### CE1 行为

应说明如何定义研究问题、选择和评价来源、处理冲突信息、从产品变化推导组织问题，以及推动利益相关者使用研究结果。

### CE2 产物

较强产物包括产品能力演进矩阵、能力瓶颈矩阵、公司和岗位编码数据集、能力原型与人才来源树、候选人证据卡、带来源追踪的研究工具和可复核报告。

### CE3 结果

结果可以表现为改变业务或People判断、扩展或纠正搜索范围、发现岗位画像错误假设、减少重复研究、提高复核效率，或使结论进入实际项目。

### CE4 可归因与可复核证据

包括版本化代码和数据、原始来源记录、明确个人贡献、被修正的假设、失败复盘以及可重复运行的分析流程。

## 10. 作者案例的组合证据

### 10.1 AI Coding Agent研究仓库

支持：`P2 + T1[AI产品/开发者工具] + G-E2 + M2 + O1/2 + D1/2[Research]`。

它证明作者能够建立从AI产品证据到组织与人才判断的方法链。

### 10.2 校园重建工具

支持：`P2 + T1/2[AI辅助软件/数据工作流] + A-W2 + G-E1/2 + D2[Product/System]`。

它说明作者承担过目标定义、Agent协作、技术取舍、异常处理和结果责任。但不能单独证明企业级AI平台、大规模采用、People战略或企业治理能力。正式公开的模块、测试和架构数字仍需再次确认。

### 10.3 Movie Night舞台项目

支持：`V2 + P2 + O2 + D2[Organization/Project]`。

它证明作者能够把异质观点转化为可执行方案，并推动不同主体完成结果闭环，但不能直接证明AI产品研究或统计研究方法。

三个案例结合形成：

> **研究判断＋AI工具实践＋跨边界组织连接。**

这种组合与目标岗位的职责机制具有较高相似性，但不能据此断言完全胜任或必然通过招聘。

## 11. 内部AI工具的责任边界

### 适合工具化

- 官方资料和岗位页面收集；
- 访问日期和页面状态记录；
- 公司、产品和岗位实体标准化；
- JD字段提取和初步编码；
- 来源链接与结论关联；
- 页面变化检测；
- 重复或相邻岗位发现；
- 候选人证据卡结构化；
- 报告初稿和一致性检查；
- 待验证项与过期信息提醒。

### 不应完全交给工具

- 决定业务真正的能力瓶颈；
- 判断不同技术领域是否可迁移；
- 把公司能力归因于个人；
- 自动淘汰候选人；
- 处理高风险组织决策；
- 生成不透明候选人排名；
- 收集私人联系方式或无关个人信息；
- 代替人工承担最终责任。

适合的工具定位是：

> **具有来源追踪、证据结构化和人工复核节点的组织能力研究工作台。**

## 12. 当前缺口

1. **目标岗位官方证据**：需恢复官方链接、完整JD、地点、状态和访问日期；在此之前不能作为A级岗位样本。
2. **中国市场岗位证据**：继续补充AI人才战略、AI Enablement、People Research、组织与人才规划等官方JD。
3. **工具原型证据**：形成“来源采集→结构化编码→人工复核→能力瓶颈与原型关联→输出证据卡或简报”的最小闭环。
4. **商业化表达**：将复杂分析压缩为一页决策简报、关键判断、风险与可执行下一步。
5. **独立复核**：增加独立编码者抽查、定义一致性检验和关键结论反向审阅。

## 13. 阶段结论

> **AI组织能力情报岗位的核心，不是比招聘团队掌握更多人才名单，也不是比工程团队更懂底层模型，而是把快速变化的AI产品能力转化为可验证的组织与人才判断，并将这些判断沉淀为可复用、可审计的研究与工具流程。**

稀缺性来自三类能力同时成立：

1. 对AI产品和技术边界具有可信理解；
2. 能够把行业变化转换为组织能力和人才问题；
3. 能够用研究、工具和组织连接推动结论进入实际决策。

目标岗位四组职责的最终解释为：

> **AI产品研究负责发现变化，公司和行业研究负责解释变化，人才Mapping负责寻找解决能力瓶颈的人，内部AI工具负责让整条证据链持续运行。**
